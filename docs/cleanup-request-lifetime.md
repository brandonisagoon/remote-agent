# Cleanup request lifetime

Owner inspection and adoption keep their existing JSON, source checks, compare-and-swap guards and request-key replay. Authenticated activity and inspection reads have a 60-second application deadline. Authenticated delivered-retirement and external-delivery adoption have a 240-second deadline. Expiration returns HTTP 504 with `REQUEST_DEADLINE`, bounded stage names and retry guidance. Completed stages are reported in `Server-Timing`; no provider response, history, path or credential is included.

Repeat a read to get fresh observations. For a lost or timed-out adoption response, replay the **same request key and exact body**. A transaction already committed before the response was lost is recovered by the existing immutable binding; do not generate a second decision. Expiration or disconnection invalidates subsequent observation checkpoints and the original transaction's pre-write and pre-commit checks. A read already in flight may finish, but its late result cannot advance acceptance. The existing pause, source, revision, resource and owner checks still run.

Bun 1.3.14 closes a silent default HTTP request around 12 seconds. Per-request `server.timeout(request, 0)` works on TCP but is inert on Unix listeners. The control socket therefore uses the supported maximum `idleTimeout: 255`, above the 240-second application deadline with a response margin. It remains owner-only (0600). Other network requests keep the default transport timeout; only the selected authenticated handlers extend it, then restore a 15-second response-write window. No global unbounded timeout, polling worker, new acceptance endpoint or credential change is introduced.

References: [Bun server timeout documentation](https://bun.com/docs/runtime/http/server#idletimeout), [upstream Unix per-request timeout report](https://github.com/oven-sh/bun/issues/43816).

## Verification

The installed `/opt/homebrew/bin/bun` is 1.3.14. Disposable loopback TCP and unique Unix socket fixtures both reset at about 12 seconds with the default configuration. With request-local timeout disabled, TCP completed at 14 seconds while Unix still reset. Unix serve-level configuration fixed the same fixture. The installed runtime accepts 255 and rejects 256 and 300 for `idleTimeout`; the workaround uses no unsupported value.

The real activity route now returns after a 14-second runtime-history read over both transports. The real authenticated legacy inspection route survives a 14-second source observation over both transports; slow adoption returns its normal JSON, and the exact request replays to one immutable binding. Another regression reproduced late adoption after the HTTP deadline before the transaction checkpoints were added. It now leaves zero bindings, including expiration after an event write but before commit. Cancellation, authentication scoping and bounded diagnostics are covered separately.

DRA-98's stored live failure measured 11.901 seconds with no PUT. A separate read-only fingerprint measurement took 4.320 seconds for 10,409 files, so fingerprinting alone did not establish the live slow stage. DRA-8's stored failure was an activity GET before its next adoption write. That route also awaits runtime history and had the same default transport exposure. These measurements establish the transport defect; they do not identify the exact unrecorded live substage. The new stage diagnostics allow the sole original owner to identify it on the next authorized continuation. No live inspection retry, adoption or cleanup was performed while developing this change.
