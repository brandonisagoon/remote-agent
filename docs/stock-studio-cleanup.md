# Stock Studio cleanup

Stock Studio workspaces have original Compose ownership receipts rather than
Drafted task labels. Their app also joins the shared proxy network. The generic
Compose cleanup rules remain unchanged; an enrolled stock group uses its exact
external ownership proof through the existing cleanup adapter and operation.

The server accepts a complete plan of three original containers, four recorded
volumes, the private default network and two registered proxy routes. Every target
binds the same original task, development purpose, project and immutable enrolled
record. Container IDs, volume names and default-network ID must match the
original resource. The routes select the original workspace container, the same
shared proxy and configuration inode, and ports 3200 and 8100. Shared proxy and
network objects are preservation facts, never removal targets.

The configured observer verifies the external ownership bytes and physical
lifetimes. The server freezes that result through its existing preparation and
confirmation contract; it does not read provider state inside SQL or introduce
another authority endpoint. Final confirmation requires every prepared target
absent, including routes. The enrolled proof and shared configuration must remain
outside source/evidence capture roots. Their exact descriptors remain available
after the original source has been captured. Shared configuration content can
change for unrelated routes; its held filesystem identity and the exact selected
route digests remain bound.

Retained migration resources continue to use their existing preservation path.
Stock cleanup cannot adopt a different member, omit a route, replace a shared
configuration inode or relabel a changed provider object. Client effect and
lost-response recovery tests, full composition, protected delivery and disposable
live acceptance remain separate from this server schema checkpoint.
