# Saved archives during v1 finalization

DRA-190 lets the original primary finish an existing v1 preparation while registered saved archives remain intact. It does not mark them Released, move their files, replace the tooling pin, or edit the original preparation, owner grant, completion contract or historical metadata.

After current completion/retirement authority passes, preparation independently verifies every eligible `evidence-archive` receipt against an exact registered archive root. Root metadata must contain a pinned `manifest` and optional `addenda`, each with a relative path, SHA-256 and optional entry count. The primary JSON manifest binds the task, issue and accepted merge commit. Its `entries` use `archivePath`, `sha256` and optional `bytes`; addenda have the same member shape. Nested directory/file receipts must belong to exactly one root. Any registered cleanup-receipt hash must also match.

Manifest-covered files retain their historical attribution. Other existing private files, such as an archive README or builder, are inventoried separately as newly observed ancillary material. They are preserved and rechecked; they are not mislabeled as historical manifest evidence. The separate v2 restore verifier still requires complete manifest coverage with no ancillary exemption.

The immutable `finalization-archive-retention` event binds the original v1 preparation's exact serialized bytes/revision, contract, primary, task/tooling identity and resource identities/states. It records every private inode, mode, size and content hash. A partial unique index permits one supplement per original primary/task. Repeated preparation and lost responses use that same proof. No model-written metadata or resource-kind exemption grants retention.

Files must be owned, unshared regular files with mode 0600; directories must be owned with mode 0700. Symlinks, special files, changed identities, stale authority and overlapping active cleanup scopes are rejected. Limits are 8 MiB per manifest, 21 manifests, 10,000 declared members, 10,025 observed files, 250,000 inventory entries and 512 MiB total archive bytes. Hashing streams through a single 64 KiB descriptor-owned buffer. Archive filesystem work stays outside SQLite transactions.

Task/list projections expose only the immutable receipt and current resource binding. They do not read archive files. If that binding becomes invalid, `archiveRetentionRequired` remains and no usable proof is returned. Actual prepare, confirmation and completion publication independently verify contents. `POST /api/sessions/:sessionId/archive-retention` checks contents against exact saved proof/preparation revisions, digest and finalization key; callers cannot supply new paths or authority. Drafted uses it before direct archive operations and closed/expired upkeep. Generic resource PUT cannot release or rewrite proof-bound archives. Missing/changed files preserve the remaining task.

Legacy evidence cleanup derives overlap boundaries from actual eligible v1 cleanup receipts. A tooling-purpose retained parent is not a whole-tree deletion operation; changing it into an active cleanup scope still invalidates the proof. This fixes DRA-12 without relocating files or rewriting its original receipts. Unrelated unreleased resources continue to block closure.

Release additive migration `20261030080000_saved_archive_retention` and matching Drafted capability together through the supported updater. Existing primaries resume their original finalization key/grant under the existing tooling pin. Old clients reject the added strict wire field instead of silently discarding it. The existing validated control timeout can be selected for large archives; a timeout grants no cleanup permission and the same saved proof is inspected on retry.
